| サービス | 用途 | 料金（資料準拠） |
|---|---|---|
| Supabase | 認証 / DB(PostgreSQL+RLS) / Storage / Edge Functions | 従量（無料枠あり） |

## 10.2 環境変数一覧（代表）

### Supabase
| 変数 | 区分 | 用途 |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | 公開 | プロジェクト URL |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | 公開 | クライアント用 anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | 機密 | サーバー処理（RLS バイパス・要テナント検証） |

### Stripe（`08`）
`STRIPE_SECRET_KEY` / `STRIPE_WEBHOOK_SECRET` /
`NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY` / `STRIPE_PRICE_STARTER` / `STRIPE_PRICE_PRO`

### LINE / Brevo（`09`）
`LINE_CHANNEL_ACCESS_TOKEN` / `LINE_CHANNEL_SECRET` /
`BREVO_SMTP_HOST` / `BREVO_SMTP_USER` / `BREVO_SMTP_PASS` / `BREVO_API_KEY` / `MAIL_FROM`

### Google OAuth
Supabase ダッシュボードの Auth プロバイダ設定に Client ID / Secret を登録。

### アプリ
`NEXT_PUBLIC_APP_URL`（リダイレクト・PDF リンク用）

> 機密値は Vercel の環境変数（Production/Preview/Development で分離）に保管。
> 本ドキュメントには**実値を記載しない**。

## 10.3 CI/CD

- 資料は GitLab CI（lint/test/build/deploy 自動化）を記載。本構成では:
  - **Vercel Git 連携**で push → Preview/本番デプロイを自動化。
  - **GitHub Actions** を併用し lint / type-check / test / build を PR で実行（品質ゲート）。
  - Supabase migrations は CI で適用（`supabase db push` 等）。

### パイプライン（推奨）
```
push/PR → GitHub Actions (lint, tsc, test, build) → Vercel Preview Deploy
main マージ → Vercel Production Deploy + Supabase migration 適用
```
