# 02. 機能要件

各機能を `FR-x` 形式で定義する。入力項目は `04_データモデル.md`、画面は
`05_画面一覧.md`、API は `06_API設計.md`、権限は `07_認証認可.md` と対応する。

凡例: 権限 = 経営者(Owner) / 管理者(Admin) / スタッフ(Staff) / 顧客(Customer)

---

## FR-1 現場（Site）管理 CRUD

### 概要
清掃対象の現場（ビル・店舗・住宅等）を一元管理する。

### 機能詳細
| No | 機能 | 権限 |
|---|---|---|
| 1-1 | 現場一覧表示（検索・絞り込み・ページング） | Owner/Admin/Staff |
| 1-2 | 現場詳細表示 | Owner/Admin/Staff |
| 1-3 | 現場新規登録 | Owner/Admin |
| 1-4 | 現場編集 | Owner/Admin |
| 1-5 | 現場削除（論理削除） | Owner/Admin |
| 1-6 | 担当スタッフの割当 | Owner/Admin |

### 入力項目（`sites`）
- 現場名（必須）
- 住所（必須・郵便番号・都道府県・市区町村・番地・建物名）
- 緯度・経度（住所からジオコーディング、または手動。GPS 到着判定に使用）
- 担当スタッフ（複数可）
- 顧客（取引先。任意。PDF 報告書送付先と紐づく）
- 契約内容（契約種別＝定期/スポット、清掃範囲、頻度、契約金額、契約期間 等）
- メモ、ステータス（稼働中/休止/解約）

### 受入基準
- [ ] 必須項目未入力時はバリデーションエラーを表示し保存されない。
- [ ] 自テナントの現場のみ閲覧・編集できる（他テナントの現場は不可視）。
- [ ] プラン上限（Free 3 件 / Starter 20 件 / Pro 無制限）超過時は新規登録不可で
      アップグレード導線を表示する（`08`）。
- [ ] 住所入力で緯度経度が取得され、FR-5 の到着判定に利用できる。

## FR-2 作業指示書（WorkOrder）管理 CRUD

### 概要
現場・スタッフ・日程に対する作業の指示を作成・管理する。

### 機能詳細
| No | 機能 | 権限 |
|---|---|---|
| 2-1 | 作業指示一覧（フィルタ: 現場別/スタッフ別/日程範囲/ステータス） | Owner/Admin/Staff |
| 2-2 | 作業指示詳細 | Owner/Admin/Staff |
| 2-3 | 作業指示新規作成 | Owner/Admin |
| 2-4 | 作業指示編集 | Owner/Admin |
| 2-5 | 作業指示削除 | Owner/Admin |
| 2-6 | ステータス遷移（未着手→対応中→完了→確認済） | Staff（自分の指示）/ Admin |

### 入力項目（`work_orders`）
- 対象現場（必須・FR-1 参照）
- 担当スタッフ（必須・複数可）
- 作業日（または日程範囲：開始日〜終了日）、時間帯
- 作業内容（チェックリスト・指示文）
- 優先度、ステータス、備考

### フィルタ要件
- 現場別、スタッフ別、日程範囲（from-to）、ステータスで AND 絞り込み。
- スタッフは自分に割当てられた指示を既定表示。

### 受入基準
- [ ] 現場別・スタッフ別・日程範囲フィルタが単独/複合で機能する。
- [ ] スタッフは自分の担当指示のみステータス更新できる。
- [ ] 作成・更新時に FR-3（LINE 配信）をトリガーできる。

## FR-3 作業指示配信（通知アプリ / LINE）

### 概要
作業指示をスタッフ全員（または対象スタッフ）に LINE Messaging API で自動送信する。

### 機能詳細
| No | 機能 | 権限 |
|---|---|---|
| 3-1 | 作業指示作成/更新時に対象スタッフへ自動配信 | Owner/Admin |
| 3-2 | 手動再送（指定スタッフ/全員） | Owner/Admin |
| 3-3 | 配信結果のログ表示（成功/失敗/未連携） | Owner/Admin |
| 3-4 | スタッフの LINE 連携（友だち追加 + アカウント紐付け） | Staff |

### 連携仕様（詳細 `09`）
- LINE Messaging API（Push Message）を Vercel Route Handler から送信。
- メッセージ内容: 現場名・住所・作業日・作業内容・アプリ詳細への遷移リンク。
- スタッフは LINE の `userId` を `profiles` に保持して宛先解決する。
- 未連携スタッフにはアプリ内通知 + メール（Brevo）でフォールバック。

### 受入基準
- [ ] 作業指示作成時、対象スタッフの LINE に通知が届く。
- [ ] 配信成功/失敗が `notification_logs` に記録され、画面で確認できる。
- [ ] LINE 月間無料枠（200 通）超過に備え送信失敗をハンドリングする。

## FR-4 現場報告 + 写真アップロード

### 概要
スタッフがスマホで作業完了を報告し、写真を最大 5 枚アップロードする。

### 機能詳細
| No | 機能 | 権限 |
|---|---|---|
| 4-1 | 作業指示に対する完了報告作成 | Staff |
| 4-2 | 写真アップロード（最大 5 枚・カメラ起動/ギャラリー選択） | Staff |
| 4-3 | 報告の閲覧 | Owner/Admin/Staff |
| 4-4 | 報告の修正（提出前/差戻し時） | Staff |
| 4-5 | 報告の承認/差戻し | Owner/Admin |

### 入力項目（`reports` / `report_photos`）
- 対象作業指示（必須）
- 完了コメント、作業実績（実施チェックリスト）
- 写真（最大 5 枚・Supabase Storage 保存・サムネイル生成）
- 報告日時、ステータス（下書き/提出済/承認済/差戻し）

### 受入基準
- [ ] 写真は最大 5 枚まで。6 枚目以降は追加不可で上限を明示。
- [ ] 画像はクライアント側でリサイズ/圧縮してアップロードする（通信量削減）。
- [ ] スマホのカメラから直接撮影・添付できる。
- [ ] 自テナント・自担当の報告のみ操作できる（RLS）。

## FR-5 GPS 到着確認

### 概要
スタッフ端末の位置情報と現場座標を比較し、現場到着を自動記録する（不正出勤防止）。

### 機能詳細
| No | 機能 | 権限 |
|---|---|---|
| 5-1 | 「到着」操作時に端末位置を取得し現場座標と距離判定 | Staff |
| 5-2 | haversine による距離計算（しきい値 **200m** 以内で到着と判定） | システム |
| 5-3 | 到着履歴の記録・閲覧 | Owner/Admin/Staff |
| 5-4 | しきい値外/位置取得失敗時のハンドリング（手動申請・要承認） | Staff/Admin |

### 仕様
- 位置情報は Web 標準 `navigator.geolocation` で取得。
- 距離計算は haversine 公式を Route Handler（サーバー側）で実施し、改ざんを防止。
- 到着レコード（`arrivals`）に座標・距離・判定結果・時刻を保存。
- **Pro プラン限定機能**（`08`）。

### 受入基準
- [ ] 現場 200m 以内で「到着」すると到着が自動記録される。
- [ ] 200m 超では到着扱いにならず、理由付き手動申請（要承認）に誘導する。
- [ ] 位置情報の許可拒否/取得失敗時に適切なエラーと代替手段を提示する。

## FR-6 顧客報告書 PDF 自動生成

### 概要
現場写真・担当スタッフ・完了コメントを 1 クリックで高品質 PDF にし、顧客へ
品質証明レポートとして送付する（独自差別化機能）。

### 機能詳細
| No | 機能 | 権限 |
|---|---|---|
| 6-1 | 報告（FR-4）から PDF 生成 | Owner/Admin |
| 6-2 | PDF プレビュー・ダウンロード | Owner/Admin |
| 6-3 | PDF を顧客へメール送付（Brevo） | Owner/Admin |
| 6-4 | PDF の保存・再取得（履歴） | Owner/Admin |

### PDF レイアウト（最低要件）
- ヘッダ: テナント（会社）名・ロゴ・発行日
- 現場情報: 現場名・住所・作業日
- 担当スタッフ、完了コメント
- 作業写真（複数枚レイアウト）
- 到着確認情報（あれば）、フッタ（会社情報）

### 生成方式（詳細 `09`）
- 推奨: Vercel 上で HTML テンプレートを Puppeteer/Playwright により PDF 化、
  または `@react-pdf/renderer`。生成物は Supabase Storage に保存。
- 譲渡資料の WeasyPrint（Python）は別スタック前提のため代替（`09` で比較）。
- **Pro プラン限定機能**（`08`）。

### 受入基準
- [ ] 報告データから 1 クリックで PDF が生成される。
- [ ] 写真・担当・コメント・現場情報が PDF に正しく反映される。
- [ ] 生成 PDF を顧客メールアドレスへ送付でき、送付ログが残る。

## FR-7 横断要件

- すべての一覧は検索・絞り込み・並び替え・ページングに対応。
- すべての書き込み操作は監査の観点から作成者・更新日時を保持。
- すべてのデータアクセスは RLS により自テナントに限定（`04`/`07`）。
- プラン上限・機能ゲートは `08` に従い UI/サーバー双方で強制する。
