# Kaito UI/UX 設計原則 — 「AIっぽくない、自分らしいプロダクト」を作るための指針

> 出典: Kaito本人が Claude Code に打ち込んだ全セッションの指示（664メッセージ）と、実際にディスク上に作った成果物コード（LP: alta / bronco / ねこふる / BKM、業務UI: line-portfolio / project1）を、4体のエージェントで多角的に分析して逆算したもの。
> 用途: このリポジトリ（trendlinks-system-2）を含む、今後のすべてのUI実装の判断基準。

---

## 0. 核となる一文

> **「アクセントは1色。残りは階層。面には肌理。色は素材から。文言とUIは必ず一致。アニメは役割があるものだけ。重要操作は人間が最終確認。そしてスマホ実機で必ず一度崩して直す。」**

Kaitoのデザインは「**AIの匂いを消す**」ことが最上位の品質基準。彼は配色・レイアウト・文言・モーションを自前のチェック観点で能動的に監査する。対照例として、彼の初期作 BKM（紫→ピンク45度グラデ＋shimmer＋等間隔カード）が"卒業前＝AIっぽい"、alta/bronco（世界観トークン＋ノイズ＋非対称＋演出）が"現在地"。この差分こそが、AIっぽさを抜く具体的手順そのもの。

---

## 1. 「AIっぽいUI」を避けるための原則（最重要）

Kaitoが自ら言語化した「AIの匂い」検出フレーム（4観点）:

| 観点 | AIっぽい兆候（避ける） | Kaito流の回避策 |
|---|---|---|
| **配色** | 安易なネオン/紫青グラデ、無難な「黒+金」高級色、テック系テンプレ色 | **素材・ブランドの実色から起こす**。アクセントは1色に絞り、固有名で意味づけ |
| **レイアウト** | 3カラム等間隔カードの単調な並列、緩急のない一律な余白/Padding、中央寄せヒーロー＋3特徴 | **非対称グリッド**（例 1.2fr/1fr）、緩急のある余白、視線を対角に流す |
| **文言** | 「革新的な」「次世代の」「シームレスな」等の抽象ビジネス語、絵文字・英語ラベル多用 | **具体語**で書く。CTAは「動詞＋具体名」。文言とUIを必ず一致させる |
| **インタラクション** | 全要素一律フェードアップ、実用性のない過剰アニメ、デフォルトのコンポーネントそのまま | 出現は1種に統一、**役割の違うモーション**だけ作り込む。面に薄いノイズ/肌理 |

**実装で効く具体テクニック:**
1. **アクセントは1色**。残りは ink（文字3段階）＋ line（境界2段階）＋ 面（白／極薄）。状態色は `bg / line / ink` の3点セットで設計する（「とりあえず緑=成功・赤=エラー」の浅さを消す）。
2. **グラデは"面の塗り"でなく"光源"**。`radial-gradient(... at 78% -10%)` のように非対称な位置に置くだけで手作り感が出る。
3. **面に肌理を足す**。`opacity:.03〜.07` のノイズを1枚（`mix-blend-mode: soft-light/overlay`）で、ベタ塗りのAI感が消える。
4. **影は2段重ね**（内側 `inset` ハイライト＋外側ドロップ）。ただし**業務UIでは影をほぼ消して境界線で構造を出す**（用途で切替）。
5. **タイポのコントラスト**: 見出し＝個性的書体＋タイト字間／本文＝Noto・広い行間。英字ラベルは `letter-spacing` を大きく。**数値は必ず `tabular-nums`**。
6. `@media (prefers-reduced-motion: reduce)` を必ず入れる（配慮の有無がAI生成物との差）。

## 2. Kaitoの独自性 = 徹底した「ユーザー行動の最適化」

ここが最大のオリジナリティ。彼は「見た目」より「**操作の摩擦をゼロにする**」ことに執着する。

### 2-1. 引き算 — 動線から重さを削る
- **「いらない」「じゃんじゃん削る」「承認フローはいらない」** が最頻の口癖。不要なフォーム・項目・段は即削除。
- 入口の認知コストを0に：「**LPとログインを完全削除して即システム**」「ログインはもっとシンプルに」。
- ボタンは数個に絞り、残りは三点メニューに集約（「ボタンは4つに絞る」）。

### 2-2. 入力負荷と表記揺れを「構造」で潰す
- **階層化ドロップダウン**で「入力の手間を省く＋表記揺れを防ぐ」を同時に解決（区分→項目）。
- 自由入力よりチップ/セグメント選択。`:active{transform:scale(.98)}` で押した感触。
- **リアルタイム自動計算**で誤入力を封殺。再計算は自動。
- 数値は等幅（`tabular-nums`）で桁を揃え「業務ツールの信頼感」を出す。

### 2-3. 現場 = スマホ、を前提に設計
- **「どのデバイスでも2列以上」「見切れない」「アスペクト比確定」** を要件化（スマホ縦積みの単調さを拒否）。
- 入力欄 `font-size:16px` でiOS自動ズームを殺す。最小タップ48px。`env(safe-area-inset-bottom)` で固定CTAを親指に届かせる。
- 紙を使わずモバイルで完結（写真提出→パース、手書きサイン、GPS）。LINE/LIFFで1タップ。

### 2-4. 取り返しのつく設計 / 信頼
- **「AIは下書きを作るだけ。最終保存は人間」**＋差分確認。削除は**論理削除（無効化）**。
- GPS監視のような心理的圧は出さない。既存習慣（Excel/スプレッドシート/LINE）を壊さず橋渡し（CSV出力等）。

## 3. 「手触り」を作る実装パターン（成果物コードから抽出）

- **デザイントークンを `:root` に集約**（accent1色＋ink3段＋line2段＋面＋状態3色＋`--radius/--tap/--header-h`）。画面間のブレを消す。
- **角丸は用途で固定し意図的に振る**（業務UI=12px前後で統一、世界観LP=硬質に小さく or 大胆に変形）。
- **セクション頭に短い罫＋eyebrowラベル**で話題の切り替わりを示す（`::before` の26px罫）。
- **ホバーは下線ワイプ／カード持ち上げ＋枠が色づく**で「押せる/見れる」を伝える。
- **人間の痕跡を残す**: iOS実機で崩して直したコメント（`font-size:16px; /* iOS のズーム防止 */` など）が最大の差別化シグナル。

## 4. この原則を trendlinks-system-2 に適用する方針（UI最適化のみ・削除なし）

> 制約: **既存のコンポーネント／機能／要件／計算ロジック／保存I/O／PDF／署名は一切削除・変更しない。** 提示層（トークン・タイポ・余白・状態表現・マイクロインタラクション）の磨き込みに限定する。
> このアプリは「暖色オフホワイト × slate × ゴールド」という**既にあるブランド**を持つ明るいB2B業務ツール。LPのダーク世界観を持ち込むのではなく、**この既存アイデンティティを"意図的で作り込まれた"レベルまで引き上げる**ことが、この文脈での「AIっぽさ消し」になる。

実施する磨き込み（すべて加点・無害）:

1. **画面用の日本語フォントを正式採用** — 現状 Geist は latin のみで、和文はOSフォールバック頼り（＝最大のAIっぽさ/素人臭の原因）。`Noto Sans JP` を `next/font` で読み込み、本文の行間・字面を安定させる。**最優先・最大効果・低リスク。**
2. **デザイントークンの拡充**（`globals.css`、加点のみ） — ink 3段／line 2段／状態色 bg・line・ink セット／フォーカスリング変数／カード影・hover の標準化。既存トークンは消さず追加。
3. **共有UIプリミティブの磨き込み**（`ui.tsx`、クラス契約は維持） — ボタンの `:active` 押下感、入力フォーカスの質、カードの罫＋控えめ影、StatCard に等幅数字、Badge/EmptyState の精緻化。
4. **AppShell / ナビの仕上げ** — アクティブ状態・ホバー・eyebrowラベル・粘着ヘッダーの質感。情報密度の緩急。
5. **ログイン画面をテーマに統一** — 入口だけ `bg-slate-50` で浮いている → 暖色テーマ＋ブランドに合わせ、Kaitoの「ログインはシンプルに」を踏襲。
6. **状態表現の底上げ**（加点） — 共通スピナー等のローディング表現、金額の等幅化、フォーカス可読性。
7. `prefers-reduced-motion` 対応とスクロール/選択など細部の一貫化。

**やらないこと:** 機能追加、フォーム項目の増減、計算式変更、PDF/署名/Supabase/マスターのロジック変更、ルートやコンポーネントの削除。

> **適用範囲の判断（重要）**: LPで使う"芸術寄り"の演出（フィルムグレイン／シネマティックなアンビエント／世界観トークン）は、このB2B業務ツールには**持ち込まない**。集計データから抽出した原則のうち、ここで採用するのは**機能に効くもの＝データ駆動で最適なもの**だけ:
> - 採用: 画面用和文フォント（可読性）、ink/line/フォーカスのトークン化（一貫性）、等幅数字（業務の信頼感）、`:active`/フォーカスの触覚的フィードバック（操作確認）、スマホ前提の押下面、暖色ブランドへの統一（入口の違和感解消）。
> - 不採用: 装飾グレイン等の質感レイヤー。一度入れたが「クリーンな業務画面」には不要と判断し撤去。原則§1の「面に肌理」はLP文脈の技法であって、明るい業務UIの最適解ではない。
